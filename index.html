01
Subscriptions

Subscription cancellation

Customer example
“I want to cancel my subscription.” / “Please stop charging me.”
Ideal resolution

Goal: Cancel the correct subscription and clearly explain what happens to access.

  1. To cancel a subscription, first use the Support Master App 2.0. If the user cannot be found there, use Chargebee/Stripe.
  2. For App Store / Google Play subscriptions, do not cancel internally; send the relevant store-cancellation instructions using the store-user macro.
  3. Choose the correct type of cancelation. End-of-term cancellation stops auto-renewal and preserves access until the displayed end date. Immediate cancellation ends access straight away; use it when renewal payment attempts are occurring and need to be stopped.
  4. Check for related products. If the customer asks to cancel the main subscription, also check auto-renewing add-ons such as Infographics. If they ask to cancel only an add-on, cancel only that add-on.
  5. Use the matching macro and clearly state which subscription was cancelled, whether access remains available, and the exact access end date.

Tools to check

  • Support Master App 2.0
  • Chargebee
  • Stripe
  • BackOffice
  • Payrails

Macros

  • All_Brands:: Cancel - Subscription is cancelled (At the end of the billing period)
  • All_Brands:: Cancel - Add-on subscription is cancelled (At the end of the billing period)
  • All_Brands:: Cancel - Payment Due (for the applicable failed-collection termination flow)
  • Cancel (Store users) - SmartyMe (or Nexera/Glacy)
02
Payments

Refund request

Customer example
“I want a refund.” / “Please return the money charged to my card.”
Ideal resolution

Goal: Identify the transaction and follow the current refund workflow for the correct product and payment method.

  1. Identify the product and account, then clarify which payment or payments the customer wants refunded.
  2. Check the refund_eligible / refund_not_eligible ticket tags and follow the current refund flow for the specific case.
  3. Process refunds primarily within the Support Master App 2.0. If a user cannot be found in this app, or if a refund cannot be completed there, use Chargebee/Stripe as a fallback option
  4. For App Store / Google Play purchases, send the customer the relevant store refund instructions.
  5. Check whether the transaction is Captured or only Authorized / uncaptured. If it was not captured, do not describe it as a refund; ask for cancellation of the authorization in Slack channel cc_x_payments.
  6. PayPal and Paddle payments follow the documented immediate-refund route rather than the standard refund flow.
  7. For serious legal threats, immediately refund all payments the customer requests, following the internal legal-threat procedure.
  8. If a customer later says the refund has not arrived, find the ARN/STAN in Stripe and send it using the relevant status / ARN-STAN macro.

Tools to check

  • Support Master App 2.0
  • Chargebee
  • BackOffice
  • Stripe
  • Payrails

Macros

  • All_Brands:: Refund - Refunded (By the agent)
  • All_Brands:: PayPal: Refunded: 180-days policy
  • All_Brands:: Refund - Status / ARN-STAN
  • Cancel (Store users) - SmartyMe (or Nexera)

When to escalate

Use Slack channel cc_x_payments to request cancellation of an uncaptured / unauthorized payment or for other payment-related questions.

03
Payments

Payment not found / No access after payment

Customer example
“I paid, but I still can’t access the app.”
Ideal resolution

Goal: Find the email address and paid profile associated with the customer’s payment.

  1. Start with the customer’s payment screenshot, if provided. Check the merchant descriptor, amount, currency, date and time, and payment method to confirm that the payment relates to our product.
  2. Search Chargebee and Stripe using the supplied email and reasonable variations: possible typos, personal or work email addresses, and name fragments.
  3. If the payment is still not found, request any other email addresses the customer may have used and additional payment details. Search by the last four card digits, amount, charge date, and issuing bank in Payrails or Stripe as appropriate.
  4. Remember that Apple Pay / Google Pay wallet card digits may differ from the physical card’s last four digits.
  5. If you find a possible email, partially mask it when asking the customer to confirm it. Do not reveal the full address, and ensure that the email address is not presented as a clickable link
  6. After each customer-facing message while investigating, set the ticket to Waiting for Customer. Adapt the macro and do not ask again for information already provided; review screenshots carefully.
  7. If the purchase was through App Store / Google Play and cannot be found, request the information needed for technical escalation using the dedicated store-purchase macro.

Tools to check

  • BackOffice
  • Stripe
  • PayPal / Paddle
  • Payrails
  • Chargebee

Macros

  • All_Brands:: Not_found - Payment not found
  • All_Brands:: Not_found - Payment not found - 2nd step
  • All_Brands:: Header - Payment successfully located
  • All_Brands:: Apple Pay Payment Method
  • All_Brands:: Not_found - Email Address Verification Needed
  • All_Brands:: Payment not found - Purchase via Facebook/Instagram
  • All_Brands:: Payment not found - Purchase via App Store/Google Play

When to escalate

If an App Store/Google Play user cannot be located, request the relevant store user data and create a technical task. If the user still cannot be found, reach out for assistance in the #cc-help Slack channel, providing a link to the support ticket, a summary of the checks already performed, and all available information regarding the client or their payments.

04
Payments

Unauthorized or unrecognized charge

Customer example
“I don’t recognize this charge. What is it for?”
Ideal resolution

Goal: Investigate the transaction and respond based on the evidence and the customer’s tone.

  1. Review the purchase in Support Master App 2.0, Chargebee, Stripe, or BackOffice. Confirm the product, profile, transaction amount, currency, status, and relevant timestamps.
  2. If the message is neutral and the customer has not requested cancellation, use the Neutral Unauthorized Purchase Inquiry macro and do not cancel automatically.
  3. If the customer is demanding, aggressive, or implicitly threatening, follow the documented Negative path: cancel to the end of the billing cycle and use the Negative macro.

Tools to check

  • Support Master App 2.0
  • Chargebee
  • Stripe / Payrails
  • BackOffice

Macros

  • Unauthorized Purchase Inquiry (Neutral)
  • Unauthorized Purchase Inquiry (Negative)

When to escalate

Escalate serious legal threats to the Legal Team through the documented process. Contact the payment team for payment-related questions.

05
Subscriptions

Subscription and billing information

Customer example
“What subscription do I have?” / “When will I be charged again?”
Ideal resolution

Goal: Explain the customer’s exact plan and billing terms using their own subscription records.

  1. Confirm the correct account and check the product, subscription duration, current status, next billing date, and exact plan.
  2. Check every purchase separately. The main subscription, auto-renewable add-ons such as Infographics, and one-time purchases such as workbooks may have different billing terms.
  3. Before replying, verify the actual amount, currency, promotional price, full renewal price, and billing interval in the payment record.
  4. Choose the product- and plan-specific Sub_info macro, then personalize it to match the verified subscription.
  5. Explain which items renew automatically and which were one-time purchases. If the customer wants to stop future charges, provide the appropriate cancellation instructions and the access end date.

Tools to check

  • Support Master App 2.0
  • Chargebee
  • Stripe
  • BackOffice

Macros

  • Sub_info (choose the exact plan/add-on variant and product)
06
Access & login

Login and account access

Customer example
“I can’t log in to my account.”
Ideal resolution

Goal: Find the correct profile, verify registration and subscription status, and resolve or escalate the access issue.

  1. Find the profile in BackOffice and compare contact_email with auth_email. Check for duplicate profiles and confirm the paid subscription is linked to the profile the customer is trying to access.
  2. If auth_email is missing, the user may not be registered. Follow the documented registration route and create the registration link using https://web.smartymeapp.com/sign-up?sf-user= followed by the BackOffice user ID.
  3. Check subscription status and end date. If the end date has passed, access has expired; if a non-renewing subscription ends in the future, access should remain available.
  4. Remind the customer that a Magic Link is valid for 60 minutes and must be opened on the same device on which it was requested. Ask them to request a new link and check spam/junk.
  5. If the link still fails, check internet connection and VPN, restart the app/browser, clear cache, and update or reinstall the app if appropriate.
  6. Verify whether the user’s payment has definitely gone through. Check the status in Payrails: Authorized means funds are reserved; Captured means funds were charged; Failed means the payment did not complete successfully. If the payment was only authorized and not captured, use No Subscription Created - Pending Authorization and request authorization cancellation in Slack channel cc_x_payments. If the subscription is active but access is still unavailable, gather screenshots or a screen recording and a summary of troubleshooting, then submit a Zendesk Tech Support Request.

Tools to check

  • BackOffice
  • Tech Support Request
  • Payrails

Macros

  • SmartyMe:: Log_in:If the user is not registered
  • SmartyMe:: Log_in:If the user wants to log in with a password (Magic)
  • SmartyMe:: Log_in: already registered and confused
  • SmartyMe:: Magic Link Issue: Login with Password
  • SmartyMe:: Log_in:If the user is already registered (Magic)
  • All_Brands:: Bug - Details
  • SmartyMe:: Login_issue - Troubleshoot (App) - SmartyMe
  • No Subscription Created - Pending Authorization

When to escalate

Use Tech Support Request for auth_email changes, registration problems, restoring access, paid-but-no-access cases, or issues that remain after basic troubleshooting.

07
Account & privacy

Account or personal data deletion

Customer example
“Please delete my account and personal information.”
Ideal resolution

Goal: Distinguish a true account or personal-data deletion request from a subscription cancellation.

  1. Confirm that the customer wants account/personal-data deletion, not just to stop subscription renewal. If they only want to cancel, follow the cancellation workflow.
  2. Process current deletion requests through Support Master App 2.0. The workflow cancels active subscriptions, removes the user from Reteno, and deletes the profile in BackOffice and data in Supabase.
  3. Confirm that the correct profile is selected before submitting the irreversible deletion action.
  4. After confirming deletion in Master App, Nikki takes the ticket and sends the customer an explanation of the deletion process.
  5. For Adapty users, send the store-user deletion macro. For users of older versions (FunnelFox SmartyMe, MindScape, and Neurolift) please create a deletion request via Asana

Tools to check

  • Support Master App 2.0
  • BackOffice

Macros

  • All_Brands:: Delete (Store users)
  • All_Brands:: Delete_account - Deleted
  • All_Brands:: Delete (Freemium only users)

When to escalate

Please direct any questions regarding legal aspects or regulatory compliance to the Legal department via Asana. If you encounter issues with the data deletion process that cannot be resolved via MasterApp, please contact technical support. For old FunnelFox SmartyMe, old MindScape, and Neurolift users, please create a deletion request via Asana

08
Payments

Duplicate charges / Charged after cancellation

Customer example
“I’ve been charged twice.” / “I cancelled, but you charged me again.”
Ideal resolution

Goal: Establish the timeline and distinguish a real duplicate charge from a delayed posting or authorization hold.

  1. Review the ticket history and subscription timeline. Compare the cancellation request with renewal, authorization, and capture timestamps, accounting for the customer’s time zone.
  2. Confirm whether there are two captured charges or one payment represented by multiple attempts. In Payrails, payment retries can use the same Execution ID.
  3. If cancellation was requested before renewal but the payment was captured anyway, use All_Brands:: Cancelled but charged - Subscription not cancelled upon request and refund the confirmed overcharge.
  4. If no cancellation request was recorded before renewal, explain the timeline and apply the standard refund policy if the customer requests a refund.
  5. If the bank statement appears to show a charge after cancellation but system records are correct, use All_Brands:: Cancelled but charged - Processing delay explanation and adapt it to the case.

Tools to check

  • Zendesk ticket history
  • Chargebee
  • Stripe
  • Payrails

Macros

  • All_Brands:: Cancelled but charged - Subscription not cancelled upon request
  • No Subscription Created - Pending Authorization

When to escalate

Contact cc_x_payments when an uncaptured authorization needs to be cancelled or whenever the payment situation is unclear.

09
Technical issues

Technical issues

Customer example
“The app isn’t working.” / “I can’t access my lessons.”
Ideal resolution

Goal: Gather reproducible evidence, complete basic troubleshooting, and submit a useful technical escalation if needed.

  1. Clarify the exact feature or lesson, what the customer expected, what actually happened, and when the issue started. Request a screenshot or screen recording.
  2. Ask the customer to check the internet connection, disable VPN, restart the app or device, update the app, clear cache where possible, or try another browser.
  3. Test the issue yourself if possible and check whether it may affect multiple users. Follow the Confluence article Most common tech issues, workarounds and key things to check.
  4. For an unresolved individual issue, create a Zendesk Tech Support Request. Include the description, reproduction steps, platform/device, screenshots or video, troubleshooting already tried, and your own test result.
  5. For certain product-specific issues, use the relevant Slack channel: smartyme-bugs-report or ai-nexera-bugs-report.

Tools to check

  • App or web version
  • Zendesk Tech Support Request form

Macros

  • All_Brands:: Bug - Details
  • All_Brands:: Bug - Escalated
  • SmartyMe:: Bug - green screen loading (Android/IOS)
  • SmartyMe:: Login_issue - Troubleshoot (App)

When to escalate

Use Tech Support Request for unresolved individual issues. For applicable product-specific bugs, use smartyme-bugs-report or ai-nexera-bugs-report.

10
Product questions

Feature and product questions

Customer example
“Can I change the language?” / “Does the app support this feature?”
Ideal resolution

Goal: Give a clear and accurate answer about the requested feature.

  1. Clarify the feature, product, app version/platform, and what the customer expected to see.
  2. Determine whether the feature exists but is hard to find, is currently unavailable, or should work but appears broken.
  3. If it exists, provide verified navigation steps. If it is unavailable, explain this clearly and politely without promising a release date.
  4. If the customer reports a feature request or general feedback, share it through Ferron Feedback in MasterApp or Slack channel sm-content-product-feedback.
  5. If a feature that should work appears broken, collect platform details, reproduction steps, and a screenshot or screen recording, try to reproduce the issue, and follow the technical escalation procedure.

Tools to check

  • CrystalBall
  • Support Master App 2.0
  • App or web version

Macros

  • SmartyMe:: Feature_info (Audio lessons)
  • All_Brands:: Feature request
  • All_Brands:: Feedback Shared
  • All_Brands:: Bug - Details

When to escalate

If a documented feature is not working, collect the platform, reproduction steps, and screenshots/video, then submit a Tech Support Request.

Before you send

Final ticket checklist

  • Answer every question the customer asked.
  • Verify the profile, product, plan, amount, and payment status in the correct system.
  • Personalize the macro and double-check all dates, amounts, links, and placeholders.
  • Complete any required cancellation, refund, deletion, or escalation action — don’t only describe it.
  • Apply the appropriate tags and leave a useful internal note when escalating.
  • Set the correct ticket status and verify that the action actually succeeded.
